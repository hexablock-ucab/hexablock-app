## Objective

The team has one written domain model of the generic engine and the four variants, and a class diagram and a machine-readable class model that say the same thing, so the engine can be built from them.

## Problem

The requirements, the game rules and the class index say *what* the engine must do, but no document fixes the classes, their members, the type parameters and their bounds, the states, the events, the capabilities, the snapshots or the boundary between the engine and each variant. Without it, the four variants would be designed four times, and the class diagram that C-11a requires cannot be drawn.

## Scope

- In scope: `docs/domain-model.md`; `docs/diagrams/class-model.json`; the class diagram split by package (`docs/diagrams/class-diagram*.puml`) and its PNG exports at 2x; the legend and stereotypes in `docs/diagrams/README.md` (without DDD); the model follows ADR-0004 as accepted in PR #23 (levels declare their topology); `AI_USAGE.md`; a private interactive explorer of the class model, published as an artifact (not in the repository).
- Out of scope: production code; `AGENTS.md` §4 and `.claude/agents/architecture-reviewer.md` (they move to the planned pair of pull requests `docs/domain-model-without-ddd` in app and api); the layers diagram (D8) and the extensibility diagram; the README sections on patterns and generics (they follow the code).

## Specs

- **S1** (C-19, NFR-04): `docs/domain-model.md` lists every class of the generic engine and of the four variants with its attributes and operations; each class names its layer, its package and, where it plays one, its pattern and role.
- **S2** (C-19f): every type parameter is listed with its bound; each bound has its reason (for example `TCell extends IMergeable<TCell>` in `SlideMergeRule`).
- **S3** (C-32): the document lists every value object with its validation rule and lists every primitive that remains in the domain or the use cases, each with its justification.
- **S4** (C-19c, game-rules): the document gives the game phases (playing, paused, won, lost), what each one allows, and the transitions; "resolving" and "menu" are not phases; reaching 2048 is a notice (MERGE-1).
- **S5** (C-19c, C-06): the document lists the engine events and who publishes and observes them (Observer); none is a DDD domain event.
- **S6** (C-21, C-20): the document gives the optional capabilities (`IUndoable`, `IRedoable`, `ITimed`, `IRandomSeeded`), which variant has each, and how they reach the use cases and the screen without a type check (`CapabilitySet`).
- **S7** (FIT-4, SCORE-2, MERGE-4, FR-45, FR-66): the document states what each variant keeps in its undo snapshot: Fit keeps the board, the placements and the orientations, not the moves or the clock; Merge keeps the board, the score, the generator state and the target notice; Lines and Sort have none. The history capacity is unlimited with redo in Fit and one step without redo in Merge.
- **S8** (NFR-05, FR-16, MERGE-4): the document specifies the seeded generator (Mulberry32, cited), its state as a value object, how it is injected and how its state is saved and restored with the game.
- **S9** (C-20, C-22, NFR-01): the document draws the boundary between the engine and each variant module (factory, input of gestures, drawing of the cell, texts) and lists the files a fifth variant adds and the files it does not touch.
- **S10** (C-11a): `docs/domain-model.md` ends with a Spanish–English glossary; every element cites its requirement or game rule.
- **S11** (C-11a): `docs/diagrams/class-model.json` holds the same model as data (per class: name, stereotype, layer, package, variant or engine, type parameters with bounds, attributes with type, visibility and `{readOnly}`, operations with signature, relations with type and multiplicity, pattern, and requirement or rule).
- **S12** (C-11a): the `.puml` files are generated from `class-model.json`; every class in the JSON appears in at least one `.puml` file, with the same members; the engine and the use cases are complete, and every variant shows its `«bind»` to the engine template; each `.puml` has a PNG export at 2x.
- **S13** (C-11a): the diagrams follow UML 2.5 and the legend of `docs/diagrams/README.md`, which no longer lists DDD stereotypes.
- **S14**: an interactive explorer built from `class-model.json` is published as a private artifact: graph of classes and relations, detail on click, filters by layer, variant and pattern, search, and the warnings it computes itself (class without requirement, value object with a setter-like member, dependency from an inner layer to an outer one, variant without `«bind»`, interface without implementation, Spanish name).

## Design notes (working state, survives a context reset)

The model as designed on 2026-11-25, before any deliverable was written. Names are final unless a review changes them.

**How the deliverables are produced.** One authoring source in the session scratchpad (compact JS) → `docs/diagrams/class-model.json` → generated `.puml` files (one per view) and the generated class-reference section of `docs/domain-model.md`. Narrative sections of the document are hand-written. The generator stays outside the repo (no code in this task); offer to add it to `tool/` later. Each `.puml` header says the JSON is the source of truth.
- JSON per class: `name, kind (class|interface|abstract|enum|sealed), stereotypes, layer (domain|application|adapters|frameworks), port (input|output|null), package, folder, scope (engine|hexa-lines|hexa-fit|hexa-sort|hexa-merge|app), typeParameters[{name,bound,boundReason}], attributes[{name,type,visibility,readOnly,static,derived}], operations[{name,parameters[{name,type}],returns,visibility,static,abstract,kind}], literals (enums), relations[{type (generalization|realization|association|aggregation|composition|dependency|bind),target,label,multiplicity,role,bindings}], patterns[{pattern,role}], traces[], summary`.
- Views: `class-diagram.puml` (overview, packages and binds), `class-diagram-engine.puml`, `-application.puml`, `-adapters.puml`, `-hexa-lines.puml`, `-hexa-fit.puml`, `-hexa-sort.puml`, `-hexa-merge.puml`. PlantUML: download plantuml.jar to the scratchpad (GitHub release), run with Java 21, `!pragma layout smetana` (no Graphviz), `skinparam dpi 192` for 2x. Layer colors: domain yellow, application purple, ports green, adapters and frameworks blue; spot marks ▲ ■ ● if they render. Patterns as notes attached to participants. Only stereotypes `«Entity»`, `«Value Object»`, `«interface»`, `«Use Case»`, `«Adapter»`, `«DTO»`, `«Mapper»`, `«ViewModel»`.
- Variant binds: per variant a Dart typedef node, e.g. `HexaLinesEngine` = `GameEngine<ColorId, LinesMove, LinesState>` with a `bind` relation (bindings TCell→ColorId…), plus realizations of `IGameRules`/`IGameFactory` labeled with bindings.
- Explorer: single HTML page that embeds the JSON; warnings: class without traces; value object with a public non-readOnly attribute, a `set*` operation or a void command; relation from an inner layer to an outer one (domain < application < adapters < frameworks); variant scope without a `bind`; interface without a realization; Spanish name (word list + accents/ñ).

**Engine core (`hexablock_engine`, folder `core/…`, scope engine).**
- Geometry: `Coordinate` VO (`+components: List<int>`; only topologies read it); `ITopology` (Strategy: `origin, directions, axes, fullTurn`; `isValid, neighborsOf, step, translate, rotate (about origin), rowsAlong(axis, cells), inFixedOrder(cells), orderedTowards(direction, cells), regularShape(radius)`); `HexTopology` ([q,r] axial, Red Blob Games cited, rotation [q,r]→[−r,q+r], fixed order: r then q; single injected instance); VOs `Direction(index)`, `Axis(index)`, `RotationSteps(count)`, `Radius`, `Shape` (cells relative to origin, connected; `placedAt(anchor)`, `rotated(steps)`; holds topology), `CellLine(axis, cells)`.
- Board: `Board<TCell>` immutable VO (`+topology, +coordinates` in fixed order, `-contents`; `contains, cellAt, isEmptyAt, isFull, emptyCoordinates, occupied, neighborsOf, rows, canPlace(cells), withCell, withCells, withoutCells`), built only by `BoardBuilder<TCell>` (Builder: `regular(radius)`, `cells(...)`, `withCell`, `build()`). No bound on TCell.
- Errors: `DomainError` (abstract, `message`), `InvalidValueError`, `InvalidBoardError`, `InvalidLevelError(check)`.
- Engine: `IGameRules<TCell,TMove,TState>` (Strategy: `boardOf, validate→MoveValidation, apply→TState, resolve→Resolution<TState>, evaluate→GameEnd, outcomeOf→GameOutcome`); `GameEngine<TCell,TMove,TState>` concrete, implements `IRestorable<TState>` (`+state, +phase, /board`; `submit(move)→MoveValidation, pause, resume, restore(state), outcome(), add/removeEventListener, add/removeStateListener`). Cycle (C-19c): phase accepts? → validate → apply → resolve → evaluate → phase transition → notify. No scoring step in the engine: rules call their injected `IScoringPolicy` inside `resolve`. VOs `MoveValidation`, `RejectionReason(code)` (i18n key), `Resolution<TState>(state, events)`, enum `GameEnd {ongoing, won, lost}`, `GameOutcome(won, score?, moves?, time?, par?, thresholds?; withTime)`.
- Abstract Factory: `IGameFactory<TCell,TMove,TState>` (`gameId; createBoard, createRules, createInitialState, createCapabilities(engine)`); one factory instance per game, configured through its constructor (level, seed, clock…). `GameAssembler` (static generic `newGame(factory)`, `resumeGame(factory, state)`) → `PreparedGame<…>(engine, capabilities)`.
- Reusable resolution: `IMergeable<T extends IMergeable<T>>` (`canMergeWith, mergedWith`); `SlideMergeRule<TCell extends IMergeable<TCell>>` (`slide(board, direction)→SlideResult<TCell>(board, merged, changed)`, `canSlide(board)`; MERGE-2); `LineClearRule<TCell>` (`clearFullRows(board)→LineClear<TCell>(board, lines, clearedCells)`; LINES-1/2).
- State pattern: abstract `GamePhase` (`kind, acceptsMoves, isOver; paused(), resumed(), ended(end)`), `PlayingPhase, PausedPhase, WonPhase, LostPhase`, enum `PhaseKind`. Lines and Merge end in Lost = game over (defeat screen with score). Paused: only resume. Won/Lost terminal. Restore only while playing.
- Observer: abstract `GameEvent(kind: EventKind)`; `EventKind(name)` kebab key for audio and presentation maps; core events `MoveApplied, MoveRejected(reason), PhaseChanged(from,to), GameWon, GameLost, StateRestored`; variant events below. `IGameEventListener.onEvents(events)` (non-generic: stopwatch, audio) and `IStateListener<TState>.onStateChanged(StateChange<TState>(before, after, events, phase))` (history, session adapter).
- Capabilities (ISP): `IUndoable(canUndo, undo)`, `IRedoable(canRedo, redo)`, `ITimed(elapsed, isRunning)`, `IRandomSeeded(seed)`; `CapabilitySet` VO (`undo?, redo?, timer?, seeded?`; `none()`); `SeedRecord` implements `IRandomSeeded`. Fit: undo+redo+timer. Merge: undo+seeded. Lines, Sort: seeded only. FIT-6: the screen hides the board while paused when `capabilities.timer` exists.
- Memento: `ISnapshotable<TSelf extends ISnapshotable<TSelf,TSnapshot>, TSnapshot>` (`toSnapshot, restoredFrom`) implemented by `FitState`, `MergeState`; `SnapshotHistory<TState extends ISnapshotable<TState,TSnapshot>, TSnapshot>` implements `IUndoable, IStateListener<TState>` (caretaker; records `before.toSnapshot()` on MoveApplied; `-target: IRestorable<TState>`, `-capacity: HistoryCapacity`); `RedoableSnapshotHistory` extends it + `IRedoable` (future stack, cleared on a new move). `HistoryCapacity` VO (`unlimited()`, `steps(n)`). Merge: capacity 1, no redo; Fit: unlimited with redo. A no-change slide is rejected by validate, so it never reaches the history (MERGE-3).
- Randomness: `IRandomSource` (`state: GeneratorState; next()→RandomDraw<int>` raw 32-bit, `nextBelow(bound)` unbiased); `Mulberry32` (immutable; `fromSeed, restore`; cite T. Ettinger 2017, CC0, gist 46a874533244883189143505d203312c; caveat: not equidistributed, about 1/3 of uint32 values never appear, fine for a game); `IRandomSourceFactory` + `Mulberry32Factory` (single injected instance); `RandomDraw<T>(value, next)`; VOs `Seed`, `GeneratorState` (0..2^32−1).
- Pieces: `IPieceSource<TPiece>.next()→PieceDraw<TPiece>(piece, rest)`; `IPieceRecipe<TPiece>.draw(random)→RandomDraw<TPiece>` (Strategy); `SeededPieceSource<TPiece>(random, recipe; +generatorState)`; `FixedPieceSource<TPiece>(pieces; isExhausted, drawAll)`. States type their source as `SeededPieceSource<…>` so mappers can save the generator state (FR-16).
- Time: `Clock` (domain output port, `now(): DateTime`); `GameStopwatch` implements `ITimed, IGameEventListener` (starts on the first MoveApplied, pauses and resumes on PhaseChanged, stops on GameWon, truncates; FIT-5, FIT-6); `ElapsedTime` VO (seconds; `truncating(duration)`).
- Progress: `IScoringPolicy<TState>.pointsFor(before, after)→Score`; `IProgressModel` (`usesLevels; resultOf(outcome, at: ResultDate)→GameResult; isBetter(candidate, best?)` by RANK-1); `GameResult(score?, stars?, moves?, time?, achievedAt)`; `HighScoreProgress` (Lines, Merge; core). VOs `Score, StarCount (1..3), MoveCount, ResultDate (UTC), GoalCount`.
- Levels: VOs `GameId` (lowercase + hyphens), `LevelId` (`<gameId>-NNN`), `LevelNumber, LevelVersion, Difficulty (1..5, LEVEL-2), LevelHeader (L1 check), LevelCatalog (mergedWith: higher version wins, order by number; accessGiven(completed)→List<LevelAccess>; LEVEL-1), LevelAccess, LevelPar (moves, time), MoveThresholds (first > second)`. `ColorId` (palette red, orange, yellow, green, cyan, violet) in core because Lines and Sort share it.

**Variants (domain, folder `variants/<id>/` of `hexablock_engine`).**
- Lines (`ColorId, LinesMove, LinesState`): `HexaLinesFactory(catalog, seed, randomSources, topology, radius 4)`; `LinesState` VO (board, tray, score, streak, source: SeededPieceSource<LinesPiece>, lastTurn: ClearReport?); `LinesMove(slot: TraySlot, at)`; `Tray` (3 slots; take, isEmpty, refill), `TraySlot`, `LinesPiece(shape, color)` (no rotation, LINES-4), `PieceCatalog` (1–5 cells, LINES-5), `CatalogRecipe`; `HexaLinesRules(scoring, clearRule)`: apply places and removes from tray; resolve clears lines, scores, refills when empty; evaluate lost when no tray piece fits anywhere (LINES-6, FR-35); `Streak`, `ClearReport(cellsPlaced, linesCleared)`; `LinesScoringPolicy` (LINES-3); events `LinesCleared`, `TrayRefilled`; progress `HighScoreProgress`; typedef `HexaLinesEngine`.
- Fit (`PieceId, FitMove, FitState`): `HexaFitFactory(level, clock, topology)`; `FitLevel` «Entity» (header, figure, pieces, par, solution?); `Figure` VO (connected, no holes, FIT-1); `FitPiece` «Entity» (id, shape); `PieceId`; `FitState` VO implements ISnapshotable (board: Board<PieceId>, pieces, placements: Map<PieceId, PiecePlacement>, orientations: Map<PieceId, RotationSteps>, moves); `FitSnapshot` (board, placements, orientations; no moves, no clock); `PiecePlacement(at, rotation)`; sealed `FitMove`: `PlaceFitPiece(piece, at)`, `RemoveFitPiece(piece)`, `RotateFitPiece(piece, by)` (rotation only while the piece is free — to confirm as a rule); `HexaFitRules(par)`: moves +1, rotation +steps (FIT-4); resolve no-op; evaluate won when covered, never lost; `FitLevelBuilder` (F1–F5, L1, L2); `FitLevelProgress` (FIT-3); time added to the outcome from `capabilities.timer`; typedef `HexaFitEngine`.
- Sort (`ColorStack, SortMove, SortState`): `HexaSortFactory(level, randomSources, topology)`; `SortLevel` «Entity» (header, board shape radius 2, goal, tray: `TrayParams(seed, colors, stackSize: StackSizeRange)`, thresholds); `SortLevelBuilder` (S1, S2, L1, L2); `ColorStack` VO (tiles bottom→top, ≥1; top, topBlock, withBlockOnTop, withoutTopBlock); `TopBlock(color, size)`; `SortState` (board, offered, source, goals, moves, score, lastTurn: SortTurn?); `SortMove(at)`; `HexaSortRules(goal, cascade, scoring)`; `CascadeResolver` (SORT-1..4) → `CascadeResult`; `StackRecipe` (size uniform in range, each tile color uniform — to confirm as a rule); `SortScoringPolicy` (SCORE-1); `SortLevelProgress` (SORT-7); events `StackTransferred`, `BlockRemoved`; capability seeded (level seed); typedef `HexaSortEngine`.
- Merge (`TileValue, MergeMove, MergeState`): `HexaMergeFactory(seed, randomSources, topology, radius 2, target 2048, odds)`; `TileValue` VO implements `IMergeable<TileValue>`; `MergeState` implements ISnapshotable (board, score, source, targetReached, lastTurn: MergeTurn?); `MergeSnapshot` (board, score, source, targetReached); `MergeMove(direction)`; `HexaMergeRules(slide: SlideMergeRule<TileValue>, scoring, target)`: validate rejects a slide without change; apply slides and merges; resolve scores, spawns one tile, emits TargetReached once; evaluate lost when no direction changes the board; starts with 2 tiles (MERGE-3); `TileSpawn(value, slot: SpawnSlot)`, `SpawnSlot` (raw draw → picks a cell from the empty cells in fixed order), `TileSpawnRecipe(odds: SpawnOdds)`; `MergeScoringPolicy` (SCORE-2); events `TilesMerged`, `TileSpawned`, `TargetReached`; progress `HighScoreProgress`; typedef `HexaMergeEngine`.

**Application (`hexablock_application`).** Input ports: `StartGameUseCase, ApplyMoveUseCase, UndoMoveUseCase, RedoMoveUseCase, PauseGameUseCase, ResumeGameUseCase` → `GameSessionService`; `SaveProgressUseCase, GetProgressUseCase` → `ProgressService`; `ListLevelsUseCase, DownloadLevelsUseCase` → `LevelCatalogService`; `SaveGameUseCase, ResumeSavedGameUseCase` → `SavedGameService` (FR-16†); `SyncProgressUseCase` → `SyncService`; `GetLeaderboardUseCase` → `LeaderboardService`; `RegisterUseCase, SignInUseCase, SignOutUseCase` → `AccountService`; `UpdatePreferencesUseCase` → `PreferencesService`. Extension contract: `VariantModule` (`gameId, progressModel, texts: VariantTexts, startSession(SessionRequest)→PlayableSession, resumable: IResumableVariant?`), `IResumableVariant.resumeSession(SavedGame)`, `VariantRegistry` (Map<GameId, VariantModule>; register, moduleFor, all). `PlayableSession` (`gameId, view: SessionView, capabilities: CapabilitySet, saving: ISaveableSession?, updates: Stream<SessionUpdate>; submit(PlayerIntent), pause, resume, outcome()`). Neutral data: sealed `PlayerIntent` (`TapCell(at), DropPiece(piece: PieceRef, at), Swipe(direction), RotatePiece(piece), LiftPiece(at)`), `PieceRef(index)`, `SessionView(board: BoardView, tray: List<PieceView>, stats: List<StatLine>, phase)`, `BoardView`, `CellView(coordinate, fills: List<ColorToken>, label?)`, `PieceView`, `StatLine(labelKey, value)`, `SessionUpdate`, `SavedGame(gameId, payload)`, `StartGameRequest(gameId, levelId?, seed?)`, `SessionRequest(gameId, levelId?, seed)`, `ProgressRecord(gameId, levelId?, result)`, `LeaderboardEntry`, `UserId`, `Credentials(Email, Password)`, `Preferences`. Output ports: `IProgressRepository, ILevelRepository (headers, store downloaded), ISavedGameRepository, IPreferencesRepository, ISessionStore, IProgressGateway, ILeaderboardGateway, IAccountGateway, ILevelGateway, ISeedSource (newSeed), IAudioOutput`; the domain's `Clock` is reused.

**Adapters (layer 3) and frameworks (layer 4).** `GameSessionAdapter<TCell,TMove,TState>` implements `PlayableSession, IStateListener<TState>` (Adapter); `IIntentTranslator<TMove,TState>`, `ISessionPresenter<TCell,TState>`; per variant `HexaLinesModule/…` implements `VariantModule` (Lines and Merge also `IResumableVariant`), `LinesIntentTranslator`, `LinesPresenter`, `LinesStateMapper` (saved game), `FitLevelMapper`, `SortLevelMapper`, `MergeStateMapper`…; `LevelDto`, `ILevelDtoSource`, `LocalLevelRepository` (implements `ILevelRepository, ILevelDtoSource`), `DriftProgressRepository`, `DriftSavedGameRepository`, `PrefsPreferencesRepository`, `SecureSessionStore`, `HttpProgressGateway, HttpLeaderboardGateway, HttpAccountGateway, HttpLevelGateway`, `SystemClock`, `SecureSeedSource`, `SoundCueMap`, `ProgressMapper`, view models `HomeViewModel, LevelSelectViewModel, GameViewModel, ResultViewModel, LeaderboardViewModel, SettingsViewModel, AccountViewModel`. Layer 4: `GameScreen`, `IBoardRenderer` + `HexBoardRenderer` (+`HexLayout`), `ICellPainter` + four painters, `CellPainterRegistry` (Map<GameId, ICellPainter>), `AudioManager` (Facade, implements `IAudioOutput`, single injected instance), `CompositionRoot`.
